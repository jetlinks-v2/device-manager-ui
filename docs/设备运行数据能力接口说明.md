# 设备运行数据能力接口说明

## 1. 能力边界

`device-manager-ui` 通过 `moduleRegistry.register` 对外注册 3 个只读 DataCapability Provider、共 10 个 DataSource，供可视化资源组件消费。

- owning module：`ui/modules/device-manager-ui`
- moduleId：`device-manager-ui`
- `device-manager:monitoring`：设备汇总、位置、趋势、分类分布
- `device-manager:instance-monitoring`：设备状态与详情
- `device-manager:group-monitoring`：设备分组与分组设备
- 调用方只传简单业务参数，不接触后端 `terms`、`sorts`、`termType`
- 跨模块调用只通过公开 DataCapability，不深层引用设备模块私有代码

## 2. 统一调用与返回规范

后端 HTTP 响应中的 `result` 由 Provider 内部解包。DataCapability 对外统一返回：

```json
{
  "data": {}
}
```

分页结果统一为：

```json
{
  "data": [],
  "total": 0,
  "pageIndex": 0,
  "pageSize": 20
}
```

统一规则：

- 分页参数使用 `pageIndex`、`pageSize`，总数使用 `total`。
- 设备标识使用 `deviceId`，设备分组标识使用 `groupId`。
- 时间统一为 Unix 毫秒。
- 无法准确获取的指标返回 `null`，不使用近似值或假数据。
- 趋势返回扁平行数组；在线率缺失的时间桶保留 `null`，不改写为 `0`。

## 4. 设备监控能力

### 4.1 设备运行总览 `device.summary`

请求：

```json
{
  "scope": "iot",
  "deviceIds": ["device-001", "device-002"]
}
```

- `scope` 可不传；当前可选值只有 `iot`。
- `scope=iot` 时，Provider 统一加入物联设备范围条件。
- `deviceIds` 可不传；传入后只汇总指定设备。
- 显式传入空的 `deviceIds` 时返回全零汇总，不会退化为查询全部设备。

返回：

```json
{
  "data": {
    "total": 1286,
    "online": 986,
    "offline": 210,
    "notActive": 80,
    "other": 10,
    "onlineRate": 76.67,
    "healthyOnline": null,
    "abnormalOnline": null,
    "sampleTime": 1785283200000
  }
}
```

`healthyOnline`、`abnormalOnline` 需要关联在线设备和活动告警设备。当前设备接口无法准确计算时返回 `null`。

### 4.2 设备位置列表 `device.location.list`

请求：

```json
{
  "scope": "iot",
  "pageIndex": 0,
  "pageSize": 200,
  "state": "online"
}
```

- `pageIndex` 默认 `0`。
- `pageSize` 默认 `200`，最大 `1000`。
- `state` 可选值为 `online`、`offline`、`notActive`。
- `scope=iot` 时，Provider 统一加入物联设备范围条件。
- 坐标缺失的数据不进入位置列表。

### 4.3 设备运行趋势 `device.runtime.trend`

请求：

```json
{
  "scope": "iot",
  "startTime": 1785196800000,
  "endTime": 1785283200000
}
```

`startTime`、`endTime` 可不传，默认查询近 24 小时。Provider 在一次 `/dashboard/_multi` 中同时查询真实在线率和上行消息量，并按时间桶合并。

返回：

```json
{
  "data": [
    {
      "timestamp": 1785196800000,
      "onlineRate": 96.2,
      "messageCount": 3580
    }
  ]
}
```

### 4.4 设备类型分布 `device.category.distribution`

请求：

```json
{
  "limit": 8
}
```

`limit` 默认 `8`，最大 `20`。比例分母使用全部设备数；未分类设备与超过展示上限的分类统一聚合为 `other`，最终行数不超过 `limit`。

## 5. 设备实例能力

### 5.1 批量设备状态 `device.state.batch`

```json
{
  "deviceIds": ["device-001", "device-002"]
}
```

单次最多查询 200 个去重后的设备 ID。返回字段为 `deviceId`、`state`、`stateText`。

### 5.2 设备详情 `device.detail`

```json
{
  "deviceId": "device-001"
}
```

对外字段保持稳定：

- `orgName` 映射为 `organizationName`。
- `transportProtocol`、`transport`、`accessProvider` 按顺序映射为 `accessMode`。
- `description`、`describe` 映射为 `description`。
- 在线设备的 `lastActiveTime` 取 `onlineTime`，离线设备取 `offlineTime`；其他状态返回 `null`。

### 5.3 设备明细分页 `device.detail.page`

请求参数为 `scope`、`state`、`pageIndex`、`pageSize`；`scope=iot` 时由 Provider 统一加入物联设备范围，调用方不传递后端 `terms`。返回设备标识、名称、产品、状态、区域和最近活动时间，并携带统一分页信息。

## 6. 设备分组能力

### 6.1 分组列表 `device.group.list`

请求参数只有 `limit`，默认 `5`、最大 `100`，按 `sortIndex asc` 返回 `groupId`、`groupName`。

### 6.2 分组汇总 `device.group.summary.batch`

请求参数为 `groupIds`，单次最多 100 个。Provider 使用 `dev-group-tree` 查询当前分组及其子分组，并统一加入物联设备范围。

### 6.3 分组设备 `device.group.devices.page`

请求参数为 `groupId`、`pageIndex`、`pageSize`；`pageSize` 默认 `10`、最大 `200`。返回设备标识、名称、产品、状态和最近上报时间。

## 8. 编辑器可见参数与字段名称

本文第 3–6 节中的 `scope`、`pageIndex`、`pageSize` 等属于 Provider 底层兼容查询契约，供运行时和历史绑定继续使用，不代表全部都应显示在可视化编辑器中。

- 编辑器隐藏分页、固定设备范围及其他系统管理参数，只展示设备、设备分组、状态、时间范围和显示数量等用户可理解的筛选项。
- 设备单选、多选分别通过 `format: device-id`、`format: device-ids` 使用公共设备选择器，不按字段名猜测控件。
- 分组单选、多选复用 `device.group.options` 动态选项源并支持搜索；设备状态使用中文选项；时间字段使用时间选择器。
- 10 个面向大屏的数据能力都声明带中英文 `title` 的完整输出 schema。编辑器的字段映射显示中文名称，持久化路径和接口 JSON key 保持不变。
- 旧绑定中的分页、`scope` 和历史 query 仍继续解析，避免已有大屏失效。
