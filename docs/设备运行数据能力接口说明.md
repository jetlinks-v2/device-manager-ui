# 设备运行数据能力接口说明

## 1. 当前结论

`device-manager-ui` 对外提供 1 个只读 DataCapability Provider 和 3 个 DataSource，供设备运行总览、地图和趋势组件独立调用。

- owning module：`ui/modules/device-manager-ui`
- moduleId：`device-manager-ui`
- providerId：`device-manager:monitoring`
- version：`1`
- 不新增页面，不改变现有仪表盘接口
- 调用方只传简单 key/value 参数，不接触后端 `terms`、`sorts`、`termType`

## 2. 统一调用与返回规范

后端 HTTP 响应中的 `result` 由 Provider 内部解包。DataCapability 对外仅返回：

```json
{
  "data": {}
}
```

分页结果统一为：

```json
{
  "data": [],
  "total": 0,
  "pageIndex": 0,
  "pageSize": 20
}
```

统一规则：

- 分页参数使用 `pageIndex`、`pageSize`，总数使用 `total`。
- 设备标识使用 `deviceId`。
- 时间统一为 Unix 毫秒。
- 业务时间使用 `sampleTime`、`timestamp`、`lastOnlineTime`。
- 无法准确获取的指标返回 `null`，不使用近似值或假数据。
- 趋势返回扁平行数组。

## 3. 能力目录

| DataSource ID | 页面区域 | 模式 |
| --- | --- | --- |
| `device.summary` | 设备运行总览 | `snapshot`、`poll` |
| `device.location.list` | 设备位置分布 | `page`、`snapshot` |
| `device.online.history` | 设备运行趋势 | `snapshot` |

## 4. 接口详细定义

### 4.1 设备运行总览 `device.summary`

请求参数：无。

返回：

```json
{
  "data": {
    "total": 1286,
    "online": 986,
    "offline": 210,
    "notActive": 80,
    "other": 10,
    "onlineRate": 76.67,
    "healthyOnline": null,
    "abnormalOnline": null,
    "sampleTime": 1785283200000
  }
}
```

`healthyOnline`、`abnormalOnline` 需要关联在线设备和活动告警设备。当前设备接口无法准确计算时返回 `null`，不能直接拿告警设备总数代替异常在线设备数。

### 4.2 设备位置列表 `device.location.list`

请求：

```json
{
  "pageIndex": 0,
  "pageSize": 200,
  "state": "online"
}
```

- `pageIndex` 默认 `0`。
- `pageSize` 默认 `200`，最大 `1000`。
- `state` 可选值为 `online`、`offline`、`notActive`。

返回：

```json
{
  "data": [
    {
      "deviceId": "device-001",
      "deviceName": "1号生产设备",
      "longitude": 104.0668,
      "latitude": 30.5728,
      "state": "online",
      "stateText": "在线",
      "productId": "product-001",
      "productName": "生产设备",
      "lastOnlineTime": 1785283200000
    }
  ],
  "total": 1,
  "pageIndex": 0,
  "pageSize": 200
}
```

Geo 查询没有返回的设备标识、状态、产品或上线时间统一返回 `null`，坐标缺失的数据不进入位置列表。

### 4.3 设备在线趋势 `device.online.history`

请求：

```json
{
  "startTime": 1785196800000,
  "endTime": 1785283200000
}
```

`startTime`、`endTime` 可不传，默认查询近 24 小时；聚合粒度由 Provider 根据时间范围选择。

返回：

```json
{
  "data": [
    {
      "timestamp": 1785196800000,
      "onlineCount": 850,
      "deviceTotal": null,
      "onlineRate": null
    }
  ]
}
```

当前趋势接口只提供历史在线数量。没有每个时间桶的历史设备总数时，`deviceTotal`、`onlineRate` 返回 `null`，不能使用当前设备总数倒推历史在线率。

实现入口：

当前静态验证结果（2026-07-29）：

- TypeScript 源码语法解析通过。
- 中英文 locale JSON 解析通过。
- Provider 与 `register.ts` 的 3 个 capabilityId 一致。
- Provider 对外 query schema 仅包含简单 key/value 参数，未暴露 `terms`、`sorts`、`termType`。
- `deviceCount`、`dashboard`、`getDeviceGeoJson` 未传请求配置时仍调用原有请求形态；现有调用方无需修改。
- Provider 通过模块清单懒加载，不改变现有设备页面的主动请求链路。
- `git diff --check` 通过。
- 未执行编译、构建、`vue-tsc`、浏览器运行和真实接口验证；DataCapability 类型与运行时注册依赖 `jetlinks-web-core` 的 `codex/data-capability-registry-design` 分支，合入对应 core 变更后再做真实注册与接口联调。
